Step 2 · 역할 경계

MAGE 는 정의하고, MAI Support 는 보여 주고, MAGIC 은 만든다

MAGE (운영)

  • IAM — 사용자·부서·권한, 파일·그래프 노드 ACL 판정 API
  • 파일 원본 vault · 색인
  • LLM 게이트웨이 litellm · vLLM(Qwen3.8 포함)
  • MANA 스킬 레지스트리 · MARK
  • 지식그래프 추출·저장·뷰어 → MAI Support 로
권한 질의→모델 호출→파일 읽기→

MAI Support (서비스)

  • 문서 MESH · 대화 MAGNET · 지식그래프 graph 서비스(SQLite)
  • 공통 셸 — 한 로그인(쿠키 도메인 공유) · 한 상단바

MAGIC (개발)

  • 데스크톱 + MOJO 런타임 + MERLIN + MAGMA 탭
  • 바이브코딩 이력 = git 브랜치 · 커밋 트레일러 · git-notes 프롬프트

Step 2 · MAGIC 안의 MAGMA

프롬프트가 곧 이력이고, 되돌릴 수 있다

repo (MAGMA)
└── branch vibe/<user>/<작업명>        ← MAGIC "새 작업" 버튼
    ├── commit a1  feat: 로그인 화면 초안
    │     AI-Session-Id: S1 · AI-Assisted: 3 files
    │     └── notes refs/notes/mai  ← 턴 #1~#4 프롬프트·응답·diff
    ├── commit a2  fix: 검증 메시지     S1 (턴 #5~#6)
    ├── commit a3  refactor: 폼 분리    S2
    └── MR → main   리뷰봇 · 원장 · 승격 증명서
있음
MOJO 가 커밋마다 AI-Model · AI-Session-Id · AI-Assisted 를 강제로 박는다. 세션 전문 JSONL 도 이미 남긴다(로컬)
신규
커밋 시 그 세션의 턴 구간을 git-notes 에 붙이는 훅 · 브랜치=작업 규약 · MAGIC 의 트리 화면(MAGMA 데스크톱 흡수)
롤백
턴 되감기(커밋 전) · 커밋 되돌리기(revert·분기, 이력 보존) · 세션 재개(Session-Id 로 resume). reset --hard 는 안 준다
≈
GitHub Desktop + Copilot 커밋 속성 + Claude Code --resume — 프롬프트 전문이 git 에 따라가는 건 차별점
